## 0. Resume in one paragraph

Sonora is a zero-dependency Android TV launcher that is being pushed to a
literal 1:1 clone of the Apple tvOS 26 Home Screen and every screen reachable
from it (Settings index, all Settings sub-pages, pickers, menus, search, app
manager, tools, files, setup, screensaver). The current build already matches
the tvOS 26 home screen at rest closely and has a complete, working settings
stack. The previous pass removed the last visible clipping and fixed picker
focus. The new directive from Mitun is **not implemented yet**: make every
screen, every button press, and every transition feel like tvOS, align the
whole type/spacing/focus system to Apple's HIG, research the web exhaustively,
update the docs/plan, and do it while making the app lighter (lower RAM, no
new dependencies, no dropped features). The next concrete step is to write the
exhaustive parity plan (this file contains the raw material), then implement
the first batch: press/highlight feedback on every focusable control + HIG type
and focus calibration + measured performance work.

## 3. Current state of the code

### 3.1 Home screen — `HomeActivity.java`

What exists and is verified on the TV:

- Full-bleed wallpaper hero (`HeroBackgroundView`) with a colour wash from the
  focused app and a top/bottom scrim.
- Top-left title = the focused app's name (`Type.TITLE`). This is the single
  deliberately non-tvOS surface: a launcher has no editorial Top Shelf content.
  There is no subtitle unless there is a contextual hint (arranging, pinned,
  Settings tile, empty state).
- Clock capsule top-right (`GlassPillView`): time, optional date, a gear mark;
  opens Sonora Settings. `showDate` defaults to false, `showSeconds` false,
  clock 24-hour follows the system by default.
- Search and quick-settings circular glass buttons are **hidden at rest**
  (`alpha 0`, `focusable=false`). UP from the first grid row focuses the clock;
  its focus listener calls `setShelfTools(true)` and the two buttons spring to
  alpha 1 and become focusable. DOWN into the grid calls `setShelfTools(false)`.
  This keeps the top-right at rest identical to the tvOS reference (clock only)
  without removing the features.
- Dock: `dockBar` is a `View` with a `GlassDrawable(26f, 1f)` background,
  **elevation 0** so it sits behind the icons, not over them. It is a dark lens;
  the white "focused dock" state was deliberately removed because tvOS keeps
  the dock dark and lights the focused card.
- Grid: `Grid.compute(960dp)` → 6 columns, 2.8% side margin (27dp), 1.2%
  gutter, 5:3 icons; `BAR_PAD_DP=12`, `ROW_GAP_DP=22`, `PEEK_DP=20`.
- The grid list gets an explicit height `barPad + rows * (rowHeight + rowGap)`
  so rows below the clipped dock strip can take focus. DOWN into row 2 is
  verified.
- D-pad: `Grid.moveTarget` is pure and tested. LEFT at column 0 wraps to the
  previous row's last tile; RIGHT at the last column wraps to the next row's
  first tile. UP from row 0 focuses the clock (which reveals the tools).
- Focused tile: `AppTileView` scales the icon 1.10, raises elevation, springs
  a sheen, and leans 2.2°/1.8° in the direction of travel with a 3dp parallax
  nudge inside the card. All springs are interruptible.
- Long-press OK opens `ChoiceOverlay`: Open · Move · Add to Favourites / Remove
  from Favourites · App info · Uninstall. BACK dismisses and returns focus to
  the tile (verified).
- Move/edit mode: D-pad reorders, BACK finishes. Exists; re-verify on the TV.
- Empty state: code shows the reason and still keeps the Settings tile
  (fixed in an earlier pass; not re-tested on device without hiding every app).
- Idle watcher → screensaver after `ss_delay` (default 300s).
- `stateNotNeeded="true"`, `launchMode=singleTask`, immersive mode.
- Wallpaper decoding is off the main thread; scenes are sampled to screen size;
  the bitmap is released while the screensaver is up.

### 3.2 Settings — `ToolActivity`, `SettingsPanel`, `SettingsHomeView`,
`ScreenStack`, `SettingRow`, `Pickers`, `ChoiceOverlay`

- `ToolActivity` hosts one `ScreenStack`. Screens slide in from the right over
  the previous screen (which translates −22%), and pop back the same way.
- `Settings` index is a custom split layout: left = brand mark, "Sonora",
  "SETTINGS", selected-category summary and details; right = 8 category rows:
  Quick settings, Home Screen, Clock, Screen Saver, Apps, Tools, System, Mode.
  Selected category is restored after a rebuild. All eight fit at 960x540 dp;
  the bottom hint footer was removed in `19c6575`.
- Sub-pages use `ScreenStack` lists: DISPLAY title, CAPTION subtitle, rows with
  white focus fill, 1.02 focus scale, 8dp elevation, dark ink on white.
- `SettingRow` types: HEADER, VALUE, ACTION, TOGGLE, PUSH, DANGER, CHOICE,
  NOTE, CHECK.
- `ChoiceOverlay`: white focused row, tick, spring in/out. Focus restore after
  cancel/pick was fixed in `19c6575` by recording stack depth (`stackFocus`,
  `stackDepthAtChoice`).
- Technical mode adds extra rows (columns, 24h toggle, seconds, scene duration,
  screensaver clock, reset order).
- Settings sub-pages: Home Screen, Clock, Screen Saver, Apps, Tools, System,
  Mode. Also `AppPanel` (manage/hide/uninstall), Favourites (async push list),
  Hidden apps (async picker), `ToolsPanel`, `DebugPanel`, `FilePanel`,
  `FileServer`, `ShareActivity`, `SetupWizard`, `SetupGuide`, `QuickPanel`.
- The bottom footer ("OK to select · BACK to go back") is gone from all stack
  screens — tvOS has none and the HIG writing page says not to explain
  standard remote behaviour. This also freed the height the 8 settings rows
  needed.

### 3.3 Search — `SearchOverlay.java`

- Modal full-screen overlay; field at top (glass pill + magnifier + mic), a
  horizontal row of up to 12 result cards.
- Uses the **system IME / Gboard TV keyboard**, not a custom tvOS keyboard.
  `noKeyboard` fallback moves focus directly to results on TVs with no IME.
- Local-only: `AppSearch.filter` over the in-memory app list. No network, no
  history.
- Voice button sends `Intent.ACTION_ASSIST` with `search_type=1`; fallback is
  the keyboard.
- BACK closes the IME first, then a second BACK dismisses the overlay. Focus
  returns to the search pill.
- Press state is missing (like everywhere else).

### 3.4 Screensaver — `ScreensaverView`, `SonoraDreamService`

- Two screen-sized bitmaps alive at once, 30fps, default 60s per scene,
  2.2s crossfade, slow 1.04→1.10 scale pan, reduced motion holds still,
  scene name + credit bottom-left, time overlay optional.
- `DreamService` wrapper for the system daydream.
- Not yet checked against tvOS's aerial screensaver clock/location treatment.

### 3.5 Motion system — `Motion`, `Spring`

- Pure spring integrator + frame clock. Constants:
  `DAMPING_CRITICAL=1.0`, `DAMPING_SPRINGY=0.85`,
  `RESPONSE_MOVE=0.40`, `RESPONSE_PANEL=0.32`, `RESPONSE_FOCUS=0.30`.
- Springs animate from the current presentation value (interruptible).
- Reduced motion degrades springs to static states in `Motion`.
- No velocity handoff or momentum projection is needed for a D-pad launcher;
  the equivalent is focus-to-focus springs and press feedback.

### 3.6 Materials — `GlassDrawable`, `GlassIconPill`, `GlassPillView`

- `GlassDrawable` is a cheap Liquid Glass imitation: dark lens at rest, bright
  rim, top sheen, underside shadow; focused state is near-white
  (0.99 → 0.93 white gradient) with dark ink.
- No blur/bitmap sampling. A handful of canvas draws.
- `GlassIconPill` uses `GlassDrawable.circle`; `GlassPillView` is the clock
  capsule.

### 6.1 tvOS built-in text styles

The HIG table is in tvOS points on a 1920x1080 point canvas. Sonora runs on a
960x540 dp canvas, so the proportional dp values are half the point values:

| tvOS style | pt | leading | Sonora dp equivalent | Current `Type` |
|---|---|---|---|---|
| Title 1 | 76 | 96 | 38 / 48 | DISPLAY 34 / 1.05 |
| Title 2 | 57 | 66 | 28.5 / 33 | — |
| Title 3 | 48 | 56 | 24 / 28 | — |
| Headline | 38 | 46 | 19 / 23 | HEADING 19 / 1.22 |
| Subtitle 1 | 38 | 46 | 19 / 23 | — |
| Callout | 31 | 38 | 15.5 / 19 | — |
| Body | 29 | 36 | 14.5 / 18 | BODY 17 / 1.34 |
| Caption 1 | 25 | 32 | 12.5 / 16 | CAPTION 13 / 1.38 |
| Caption 2 | 23 | 30 | 11.5 / 15 | MICRO 12 / 1.20 |

Current faces: DISPLAY/TITLE/HEADING `sans-serif-medium`; BODY/CAPTION
`sans-serif`; MICRO `sans-serif-medium`.
tvOS weights: Title/Headline/Body/Caption are **Medium**; Subtitle 1 is
Regular. Tracking at Body 29pt is +0.40pt ≈ +0.0138em; current BODY tracking
is 0. Not a large visual gap, but the weight and the 17→14.5 size are the
biggest differences.

The minimum/default tvOS text sizes are 23pt/29pt. Proportionally Sonora's
19dp list rows are *larger* than tvOS's 29pt Body (19/540 = 3.5% of screen
height vs 29/1080 = 2.7%), so legibility is fine; do not blindly shrink to the
literal point value.

### 6.2 Safe area

HIG tvOS: inset primary content **60pt top/bottom, 80pt sides** on a
1920x1080 canvas. Proportionally on 960x540 dp that is 30dp top/bottom and
40dp sides. The measured tvOS 26 render has a ~2.8% dock side inset (~27dp at
960), which is why `Grid.MARGIN_RATIO = 0.028`. This is a deliberate documented
exception: the render is the 1:1 target, and 40dp would drop the six-column
layout. Keep it unless the user chooses HIG safe area over the render.

### 6.3 Focus and selection (tvOS section)

- Directional focus: every onscreen element must be reachable with the D-pad.
- Focused items can have up to **five states**: unfocused, focused,
  highlighted (chosen), selected, unavailable. Each must be visually distinct.
- Focused items generally **increase in scale**, gain elevation/shadow and
  illumination, and animate. Parallax gives depth.
- Lists/collections use an **entire-row highlight**; text/search fields use a
  **focus ring**.
- Do not change focus without user interaction; if the focused item disappears,
  move to a near neighbour only for discrete D-pad input.
- Focused icons must be supplied at the larger size so they stay sharp.
- Pressing the focused item should give **instant visual feedback** (a brief
  inversion/animation) — the "highlighted" state.
- Current Sonora: focused state + white list-row highlight + focus ring on the
  search field; **highlighted/pressed state is missing everywhere**.
- Current focus scales: app icon 1.10, settings row 1.02, settings index row
  1.035; no press-to-shrink.

### 6.4 App icons

- tvOS icons are **rectangular 5:3**, rounded by the system, layered for
  parallax.
- When focused, the icon elevates, sways with the remote touch surface, and the
  surface illuminates.
- Text inside a tvOS icon is discouraged unless essential.
- Current `AppIconView`: 5:3, radius 0.17×height, banner if available else a
  generated brand card, star for favourites, sheen + 2.2°/1.8° lean + 3dp
  internal parallax. Labels default off (`LABELS_OFF`), optional
  `LABELS_FOCUSED`/`LABELS_ALL`.

### 6.5 Top Shelf

- tvOS Top Shelf fills the area above the dock with the selected app's featured
  content; full-screen top shelf can play previews, swipe between items, and
  the dock slides away.
- Static fallback: 2320x720, system flips/blurs to fit 1920x1080; no implied
  interactivity.
- Sonora has no editorial content and no network, so the current compromise is
  the wallpaper + the focused app's name top-left. This is the main visual
  divergence from the reference. Options in §11.
- App banners from Android TV are normally 320x180 (16:9) and too low-res to
  fill 1920x1080, which is why `HeroBackgroundView` deliberately does not use
  them as a full-bleed hero.

### 6.6 Remotes

- Standard gestures only; combine gestures with focus movement in the same
  direction; feedback on gesture; avoid responding to inadvertent taps.
- tvOS remote: clickpad, Menu/Back, TV/Home, Play/Pause, volume, Siri.
- Android TV remote here: D-pad, OK, BACK, HOME, voice key swallowed by the TV.
- The search key on this remote does not exist as a usable key; Sonora's
  `searchKey` pref handles a search keycode when one exists.
- The user uses the remote concurrently during testing.

### 6.7 Search / text fields

- Minimize text entry on tvOS; use buttons where possible.
- Show the appropriate keyboard type; system keyboard is acceptable.
- Search should be local and predictable; result cards should be the same cards
  as the home screen.
- Current Sonora uses the system IME. It does not implement the tvOS custom
  keyboard, but Gboard TV is itself a D-pad QWERTY grid with suggestions, so
  this is a lower-priority gap than it looks. A custom keyboard is an option,
  not an automatic win (more code, more edge cases, likely more RAM).

### 6.8 Settings

- HIG Settings page has no tvOS-specific rules ("No additional considerations
  for iOS, iPadOS, tvOS, or visionOS").
- So Sonora's settings layout is free to be its own Apple-flavoured pattern.
  The current split brand/nav index is plausible tvOS Settings language; the
  sub-pages are the standard large-title + list rows.
- Do not add a remote-instructions footer (HIG writing / tvOS has none).

### 6.9 Materials, motion, accessibility, writing

- Materials: translucent layers encode hierarchy; don't stack light on light;
  bigger surfaces read thicker; use a scrim for modal tasks; vibrancy for text;
  avoid hard dividers.
- Motion: springs, interruptible, start from current value; critical damping
  by default; bounce only after momentum; mirror enter/exit paths; reduced
  motion = crossfade/static, not no feedback.
- Accessibility: every focusable element needs a meaningful content
  description; focus order must have no dead ends; reduced motion and
  transparency settings respected; text size follows the user setting (SP).
- Writing: concise, specific labels; no jargon; no unnecessary instructions;
  avoid explaining standard UI.
- Color: avoid using the same color for different meanings; ensure contrast on
  the focused white surface (current dark ink is correct).
- Layout: focused elements grow; check they don't overlap neighbours; supply
  larger assets.

### 6.10 `apple-design` skill — adapted to a D-pad TV

The skill is web-oriented, but the principles map:

- **Response:** feedback on key-down, not key-up. This is the missing
  "highlighted" state. Implement a press transform on OK/ENTER down and release
  on up/cancel.
- **Direct manipulation / velocity / momentum:** not applicable to discrete
  D-pad focus, except that focus-to-focus springs should start from the current
  on-screen value and remain interruptible (already true via `Motion`).
- **Interruptibility:** every spring must be redirectable; `Motion` already
  animates from the presentation value. Do not add fixed-duration
  `ViewPropertyAnimator`/`@keyframes`-style transitions for focus.
- **Behavior over animation:** use springs for focus, press, panel slide,
  picker, screensaver fades.
- **Spatial consistency:** panels enter/exit on the same path (ScreenStack
  already does); pickers grow out of the focused row; search appears from the
  top row; menus appear at the tile.
- **Hint in direction of gesture:** tile lean/parallax already telegraphs the
  D-pad direction.
- **Rubber-banding:** not needed for discrete focus; the grid edge should have
  a clear dead-end or wrap (current wrap is tested).

### P7 — Performance / RAM

- Baseline: 67.6 MB PSS (Java 6.2, Native 18.7, Graphics 31.9, Code 1.2,
  System 8.1) with 91 frames / 89% janky cumulative (50th 32ms). Re-measure
  after `gfxinfo reset` and while moving focus, not while idle.
- Wallpaper: already downsampled to screen size (1920x1080 ARGB ≈ 8.3 MB);
  scenes are sampled; photo URI is sampled to screen width; released under the
  screensaver. The remaining full-screen bitmap is necessary for the design.
- Screensaver: exactly two screen bitmaps; keep it that way.
- App icons: `AppManager` caches icons; check the cache size/eviction and
  whether the same banner is decoded for the home grid, search and app manager.
  The biggest win is usually decoding each icon once at the drawn size and
  sharing the bitmap; verify before adding complexity.
- Draw costs: `AppIconView` has ~9 Paint objects and a clip path per icon, plus
  a shadow each draw. The wallpaper/hero redraws gradients every draw; cache
  the static wallpaper+scrim in a bitmap layer only if measured (it costs
  another 8 MB).
- Jank: run `adb shell dumpsys gfxinfo com.mitun.sonora reset`, move focus for
  10s, then inspect. Target 60fps for focus/press; 30fps for the screensaver is
  fine.
- No new dependencies, no background threads except the short wallpaper decode
  and the visible file server; do not add a memory cache that outlives the
  screen.
- Measure per screen (home, settings, app manager, search, screensaver) and
  write the numbers into `PARITY.md`.

- Verify reduced motion for all new animations.

- Fresh boot, app data cleared if possible, first-run wizard.
- 720p/1080p/4K/overscan, font scale 1.0/1.3, RTL if feasible.
- Long-run memory (30 min idle + screensaver + return) and jank.
- Side-by-side screenshot review against the tvOS 26 reference.
- Update `PLAN.md`/`PARITY.md` with the final matrix and performance numbers.

## 13. What "1:1" can and cannot mean here

Literal parity is bounded by the platform and by honesty:

- **Cannot copy Apple assets.** No Apple icons, artwork, sounds, or fonts.
  Measurements and behaviour only.
- **No editorial Top Shelf.** Apple's top shelf is content from apps/services.
  Sonora has no content feed (and no network), so the wallpaper + app name is
  the honest substitute. Do not fake a movie poster or imply playable content.
- **No Siri, no Apple TV remote clickpad, no profile/multiuser.** The Android TV
  remote is a D-pad; use directional focus, not a pointer. Do not fake a
  profile avatar if there are no users.
- **Android TV banners are 320x180**, not 1920x1080 editorial art. A full-bleed
  banner hero would be soft; keep the wallpaper hero or use a small crisp
  crop.
- **The Settings app layout is not specified by HIG.** The Sonora split index
  is a design choice; the sub-pages are the Apple list language.
- **tvOS's focus parallax follows a finger on the touch surface.** A D-pad has
  no continuous input, so the equivalent is a directional lean/nudge on focus
  change, not a continuous parallax. Current implementation does this.
- **tvOS's Top Shelf dock can slide away** for full-screen content; Sonora has
  no content to slide away for.
- **The launcher must remain useful on Android TV**: hidden apps, uninstall,
  app info, file transfer, browser, etc. Keep those features even though tvOS
  has no equivalent. Style them in the same language.
