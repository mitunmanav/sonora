# Sonora vs Clean Your TV on the Mi TV Stick

Sonora used less memory and drew its first cold Android frame sooner.
Clean Your TV was smoother during mixed and vertical navigation. Both
cleared every horizontal deadline and had similar HOME return times.
These results cover one 2 GB Mi TV Stick and the two installed builds.

## Device and builds

Mi TV Stick, Android 11 (API 30), 2,038,028 KiB reported RAM, 1920×1080 at 59.94 Hz, 320 dpi. Both packages reported ART `speed`. Each kept its existing layout and preferences. Sonora ran first, then Clean Your TV. Thermal status was 0 at the start and end of both resource blocks.

## Protocol

1. Record the TV model, Android version, screen mode, package versions, ART compilation state and APK hashes. Keep the existing launcher layouts and system settings. Run one launcher at a time.
2. Run three trials per launcher. Each trial starts with a fresh Home launch and six seconds of settling. Verify the expected Home activity has focus. Reset `gfxinfo` before each workload.
3. Send only D-pad arrows, with a 450 ms pause after each key plus ADB and focus-check overhead. Use `scripts/tv.sh` to check the focused package before every key. Stop the trial if focus leaves the launcher.
4. Record the Android frame deadline misses, rendered frame count, frame p50/p95/p99, GPU p90, and launcher PSS. Save raw `gfxinfo` and `meminfo` dumps. Sample memory before and after the mixed walk. Use the third workload to isolate repeated dock-to-grid moves on Sonora.
5. For cold first-frame timing, start Android Settings as a common foreground screen. Force-stop the launcher and verify its process is gone before `am start -W`. Take seven samples and record the median and range. A return code or a zero time from an already-running activity is insufficient. First frame and first usable grid are different milestones.
6. Settle on Home for 15 seconds, then sample launcher CPU over four 15-second intervals, capture rendered frames during that window, and take PSS at both ends. Exclude `top`'s initial sample. Record thermal status at the start and end of each launcher block.
7. Open the same installed TV apps from each launcher’s Home screen using their Android leanback launch intent. Prewarm each app once, then repeat three times. Confirm the target app takes focus and holds it for five seconds. Measure the launcher’s background PSS alongside the foreground app and system available memory. Press actual HOME and record time until the launcher first has focus, return frame metrics and returned launcher PSS. This uses a common app entry point and keeps tile discovery and click behavior outside the timed interval. Treat focus timing as approximate because it includes polling overhead and ends before the screen’s usable state is independently verified.

| Workload | D-pad sequence |
| --- | --- |
| Mixed, matching the previous benchmark | Right ×4, Down, Right ×2, Left ×2, Up, Left ×2 |
| Horizontal | Right, Left ×6 pairs |
| Vertical | Down, Up ×6 pairs |

The same inputs can visit different layouts and animate different numbers of frames. Compare deadline-miss rates alongside frame counts and percentiles. A vertical walk only measures dock-to-grid transitions in a launcher that has that interface. Android UI frame metrics do not measure time from button press to pixels on the panel. The cumulative `gfxinfo` counters cover the full run, while each `framestats` dump contains only the tail of the run on this OS. A 4950 ms GPU histogram bucket appeared in earlier Mi TV captures and is treated as an unusable percentile on this device.

The runner takes an explicit Home component and output directory. In WSL, set `SONORA_TV` to the TV’s current ADB address and use an authorized ADB client on `PATH`.

```sh
SONORA_TV=<tv-ip>:5555 bash docs/perf/2026-11-28/run.sh \
  com.mitun.sonora/.HomeActivity /tmp/sonora-benchmark
SONORA_TV=<tv-ip>:5555 bash docs/perf/2026-11-28/resources.sh \
  com.mitun.sonora/.HomeActivity /tmp/sonora-benchmark
SONORA_TV=<tv-ip>:5555 bash docs/perf/2026-11-28/apps.sh \
  com.mitun.sonora/.HomeActivity /tmp/sonora-apps com.mitun.files org.videolan.vlc
```

## Release benchmark

For a release claim, run both orders across matched blocks (ABBA or BAAB), with at least ten independent trials per workload on each physical device. Use the runner’s `TRIALS` and `WORKLOADS` variables to rotate workload order across blocks and separate output directories to preserve each block. Include a real 1 GB Android TV, this 2 GB Android 11 TV, and an Android 12 or newer device. Record display mode, packages, layout, animation settings, thermal status, ART compilation and background activity. Retain every valid run and record each aborted trial with its reason. Report per-trial medians, spread and sample counts, and pair comparisons by device and block. Define the release’s acceptable regressions before running it. Keep CPU, memory, startup and frame metrics visible even when they favor different launchers.

Add task-equivalent journeys when both products support them. Use the same app inventory and known focus start, then capture screenshots or UI evidence that each journey reaches its endpoint. Examples include reaching a distant app, launching a common app and returning Home, and moving through a row boundary. Report launcher-specific features in their own results. Use Perfetto FrameTimeline when the OS supports it. Use an external high-speed camera with a synchronized input trigger for button-to-photon and time-to-usable-grid tests, and keep those results distinct from Android first-frame timing. [Perfetto FrameTimeline](https://perfetto.dev/docs/data-sources/frametimeline) · [Android benchmark metrics](https://developer.android.com/topic/performance/benchmarking/macrobenchmark-metrics)

For the loaded-launcher profile, freeze a representative app catalogue, pin count, wallpaper and motion settings. Populate equivalent features where possible and write down the differences. Add a 30-minute offline video-playback and Home-return loop, a file browsing loop with a fixed directory fixture, and a five-minute idle window after the last return. Log process restarts, memory lost or retained across cycles, and visible failures. Keep this profile alongside the default configuration so a memory improvement is visible under both workloads.

## Navigation results on the Mi TV

Three trials per launcher per workload. Misses are pooled across trials. Frame p99 is the median of the three per-trial p99s, with the trial range in parentheses.

| Workload | Sonora misses | Clean Your TV misses | Sonora p99 | Clean Your TV p99 |
| --- | ---: | ---: | ---: | ---: |
| Mixed | 17/1,076 (1.58%) | 0/1,040 | 28 ms (25–32) | 11 ms (10–11) |
| Horizontal | 0/1,009 | 0/1,586 | 10 ms (10–11) | 9 ms (8–9) |
| Vertical | 15/1,363 (1.10%) | 1/1,475 (0.07%) | 27 ms (25–32) | 11 ms (10–13) |

| Launcher PSS | Sonora | Clean Your TV | Sonora reduction |
| --- | ---: | ---: | ---: |
| Before mixed walk, median | 35.0 MiB | 48.1 MiB | 13.1 MiB (27%) |
| After mixed walk, median | 39.4 MiB | 53.5 MiB | 14.1 MiB (26%) |

The two launchers both rendered the horizontal workload without missing a deadline. Sonora used less memory before and after the walk, and Clean Your TV had a shorter frame-time tail in the mixed and vertical workloads. The post-walk `meminfo` Graphics median was 14.2 MiB for Sonora and 23.5 MiB for Clean Your TV. Graphics was the largest observed category difference, so a future wallpaper change should track graphics memory and frame time together.

## Clean Your TV source and WSL build

Built the existing `~/cytv-build/launcher` checkout at `be60870` using Gradle 8.9 and JDK 21. `:app:assembleRelease :app:testReleaseUnitTest` succeeded and 328 tests passed. The fresh APK’s whole-file hash differs from the installed APK’s hash. All 69 ZIP entries, including the code and resources, matched byte for byte. The TV used the original APK throughout.

- The grid uses a fixed-size `RecyclerView` and disables its item animator. Focus animations target scale, translation and alpha, with a temporary hardware layer on the ordinary card focus path. [MainActivity grid setup](https://github.com/Gathin23/cleanyourtv/blob/be6087056a1c7d4f08f3f1cc778d92374d86ef27/launcher/app/src/main/java/com/gathin/tvhome/MainActivity.java#L624-L681) · [AppAdapter focus animation](https://github.com/Gathin23/cleanyourtv/blob/be6087056a1c7d4f08f3f1cc778d92374d86ef27/launcher/app/src/main/java/com/gathin/tvhome/AppAdapter.java#L960-L1002)
- The ambient glow is painted into a single 480×270 texture and tinted on focus changes. Sonora’s dock transition concurrently draws the full-screen wallpaper and fades in the full-screen blurred backdrop. These are plausible contributors to the different frame-time tails. The navigation test alone cannot quantify each contributor. [Clean Your TV ambient glow](https://github.com/Gathin23/cleanyourtv/blob/be6087056a1c7d4f08f3f1cc778d92374d86ef27/launcher/app/src/main/java/com/gathin/tvhome/MainActivity.java#L2142-L2196) · [Sonora transition](https://github.com/mitunmanav/sonora/blob/debaa31/app/src/main/java/com/mitun/sonora/HomeActivity.java)
- Clean Your TV keeps tile artwork across ordinary app switches, then clears it under background memory pressure. Sonora also keeps wallpaper through ordinary app switches on MID and HIGH, releases it at `UI_HIDDEN` on LOW, and sheds artwork more aggressively under pressure. These policies make the launcher-behind-an-app PSS and return journey relevant to the next optimization. [Clean Your TV trim policy](https://github.com/Gathin23/cleanyourtv/blob/be6087056a1c7d4f08f3f1cc778d92374d86ef27/launcher/app/src/main/java/com/gathin/tvhome/MainActivity.java#L1363-L1382)

### Wallpaper thumbnail blur

The replacement reuses pixel sums between adjacent 5×5 windows. A unit test
compares every pixel with the previous implementation across single-pixel
dimensions, narrow edges and the production 96×54 size. Both do the same
three clamped passes with the same rounding. The extra scratch space at the
production width is 768 bytes for column sums.

| Runtime | Old kernel, median (range) | Rolling kernel, median (range) | Speedup |
| --- | ---: | ---: | ---: |
| WSL, OpenJDK 21 | 447.0 µs (430.6–460.6) | 52.4 µs (49.9–53.8) | 8.5× |
| Mi TV, standalone Android ART process | 7.87 ms (7.86–7.99) | 1.46 ms (1.44–1.52) | 5.4× |

Both measurements used the same seeded thumbnail, 1,200 warmups per side
and eight alternating-order batches of 350 calls per side. Inputs were
cloned outside the timed interval. The measurements cover the blur kernel
on a cache miss. JPEG decode, wallpaper readiness and launcher first frame
are outside that interval. [Harness](2026-11-28/BlurTiming.java) ·
[WSL timings](2026-11-28/blur-timing.csv) · [Mi TV timings](2026-11-28/blur-timing-tv.csv)

### Playback workload smoke test

On the restored `debaa31` APK, VLC played a local 720p30 H.264 test pattern.
The hardware video plane was black in ADB screenshots. The same video
SurfaceView advanced by 18.1 seconds across the 15-second foreground dwell
and the surrounding evidence captures. That establishes frame presentation.
Sonora used 34.6 MiB PSS behind playback and returned to window focus in
about 1.08 seconds with its original PID. One sample verifies the workload
path. It gives no stable estimate of return latency.
